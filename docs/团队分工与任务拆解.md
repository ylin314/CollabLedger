# 《协作账本》团队分工与任务拆解

## 1. 文档目的

本文档用于把《协作账本》完整项目拆解为可执行、可分配、可验收的任务，明确 4 位成员的职责边界、依赖关系和交付顺序。

项目目标不是只做一个比赛 Demo，而是做一个可以持续运行、支持真实小组协作、贡献留痕、AI 辅助决策和长期协作画像的完整产品。

---

## 2. 角色划分

| 角色 | 定位 | 主要职责 |
| --- | --- | --- |
| A | 后端底座 / 账号权限 / 数据库 / 部署 | 负责系统基础能力、安全隔离、数据模型、部署运维 |
| B | 核心业务后端 | 负责项目、成员、邀请、任务、打卡、评价、贡献等业务闭环 |
| C | 前端产品 / 交互 / 状态管理 | 负责页面结构、交互体验、权限展示、API 状态管理 |
| D | AI / 数据分析 / 平台接入 / 质量 | 负责推荐、风险、周报、Agent、外部平台接入、长期画像和测试部署 |

> 角色名称可以替换为真实姓名。建议每人认领一个主方向，同时在联调阶段互相补位。

## 4. 四人任务明细

## A：后端底座 / 权限 / 数据库 / 部署

### A1. 后端工程拆分

任务内容：

- 将 `backend/main.py` 拆分为分层结构。
- 建议结构：

```text
backend/
  app.py
  core/
    config.py
    security.py
    permissions.py
  db/
    base.py
    session.py
    models.py
  schemas/
  repositories/
  services/
  routers/
  tests/
```

验收标准：

- 现有 API 行为不变。
- 后端可以正常启动。
- 单元测试通过。
- 代码职责清晰，不再把所有逻辑写在 `main.py`。

依赖：

- 无前置依赖。
- 其他人的后端任务都依赖此任务。

---

### A2. 用户注册 / 登录 / 退出

任务内容：

- 实现注册、登录、退出。
- 密码加密存储。
- 登录态管理。
- 当前用户接口。

接口：

```http
POST /api/auth/register
POST /api/auth/login
POST /api/auth/logout
GET  /api/auth/me
```

验收标准：

- 用户可以注册并登录。
- 未登录访问业务接口返回 401。
- 密码不明文存储。
- 登录态可安全退出。

依赖：

- 依赖 A1。

---

### A3. 权限模型与项目隔离

任务内容：

- 实现 `owner / member / viewer`。
- 增加项目访问权限校验。
- 增加操作权限校验。
- 防止跨项目访问数据。

验收标准：

- 非项目成员不能访问项目数据。
- `viewer` 不能写入数据。
- `member` 不能删除项目或修改角色。
- `owner` 拥有管理权限。

依赖：

- 依赖 A2。
- B 的项目和成员接口依赖此任务。

---

### A4. 数据库设计与迁移

任务内容：

- 引入 SQLAlchemy。
- 引入 Alembic。
- 设计完整数据表。
- 支持数据库迁移和回滚。

核心表：

```text
users
projects
memberships
invitations
tasks
task_logs
task_checkins
task_reviews
contributions
platform_connections
project_integrations
external_events
sync_jobs
agent_sessions
agent_messages
recommendations
audit_logs
```

验收标准：

- 所有表有主键、外键、时间戳。
- 迁移脚本可重复执行。
- 空库可以初始化。
- 现有数据可以迁移或重建。

依赖：

- 依赖 A1。
- 所有业务模块依赖此任务。

### D5. 外部平台接入与数据同步

任务内容：

- 实现同步任务、失败重试和同步日志。
- 将外部平台数据标准化为统一事件。
- 将外部事件预生成为待确认贡献。
- 接入 GitHub、GitLab、Gitee。
- 接入飞书文档、飞书日历和飞书会议。
- 接入腾讯文档和腾讯会议。
- 按需接入钉钉、Zoom、Teams、Notion、语雀。
- 支持通用链接和文件证明，兜底无法自动同步的平台。

统一接口：

```http
GET  /api/integrations/platforms
GET  /api/integrations/connections
POST /api/integrations/{platform}/oauth/start
POST /api/integrations/{platform}/connections
DELETE /api/integrations/connections/{connection_id}
GET  /api/projects/{project_id}/integrations
POST /api/projects/{project_id}/integrations
POST /api/projects/{project_id}/integrations/{integration_id}/sync
GET  /api/projects/{project_id}/integrations/{integration_id}/events
```

平台示例：

- `github`
- `gitlab`
- `gitee`
- `feishu`
- `tencent_doc`
- `tencent_meeting`
- `dingtalk`
- `zoom`
- `teams`
- `notion`
- `yuque`

验收标准：

- 用户可以查看各平台的授权范围。
- 用户可以随时解绑平台账号。
- 平台凭证必须加密存储，不能返回给前端。
- 项目可以绑定多个平台资源。
- 同步失败可重试，并有明确错误原因。
- 外部事件可以转换为待确认贡献。
- 自动同步贡献不能绕过组长确认。
- Commit 数量不能作为唯一贡献标准。
- 文档、会议、代码、设计、调研等贡献类型都可以被记录。
- 平台 API 不可用时不影响手动贡献记录。
- 每个平台的数据来源可追溯。

依赖：

- A2、A3、B6。
- 平台接入依赖贡献账本和统一授权体系。
- 飞书、腾讯文档、会议系统依赖各平台开放 API 权限。
