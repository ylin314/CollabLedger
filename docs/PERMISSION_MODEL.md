# 权限模型

## 角色等级

| 角色 | 等级 | 能力边界 |
| --- | ---: | --- |
| `viewer` | 1 | 只读查看项目事实、任务、报告和已授权信息 |
| `member` | 2 | 包含 viewer 权限；可执行被授权的协作写操作 |
| `owner` | 3 | 包含 member 权限；可管理项目、成员、邀请、评价和敏感数据 |

项目访问必须同时满足：

1. 用户已登录且会话有效；
2. 用户在项目的 `memberships` 中存在；
3. 当前角色等级不低于接口要求；
4. 项目未归档，或当前操作为只读操作。

## 权限矩阵

| 操作 | viewer | member | owner |
| --- | :---: | :---: | :---: |
| 查看项目、任务、成员、报告 | ✓ | ✓ | ✓ |
| 创建/修改任务 | — | ✓ | ✓ |
| 更新本人负责的任务状态 | — | ✓ | ✓ |
| 主动打卡/填写本人工作日志 | — | ✓ | ✓ |
| 新增本人贡献 | — | ✓ | ✓ |
| 使用 Agent 对话 | — | ✓ | ✓ |
| 删除 Agent 会话 | — | — | ✓ |
| 编辑、归档、恢复、删除项目 | — | — | ✓ |
| 创建/撤销邀请 | — | — | ✓ |
| 修改角色、移除成员 | — | — | ✓ |
| 确认或争议贡献 | — | — | ✓ |
| 评价已完成任务 | —（除非被指定为该任务评审人¹） | —（除非被指定为该任务评审人¹） | ✓ |

> ¹ 任务评审人规则已实现：无评审人时仅 owner 可评价；有评审人时 owner 或该评审人可评价。

## 任务评审人与导师观察者

> 任务评审人相关能力已落地；导师观察者通过邀请链接以 `viewer` 身份加入，不直接添加成员。详见 `B_业务接口文档.md` 第 10 章。

### 任务评审人（reviewer）

- 概念：挂在**单个任务**上的授权评审人（`tasks.reviewer_id`，可空），不是项目角色。
- 指定：创建任务时指定或留空；`owner` 或**任务创建者**（`created_by`）可修改，其他成员（含负责人）不可改。
- 评价权限：
  - 任务无评审人 → 只有 `owner` 可评价（同现状）。
  - 任务有评审人 → `owner` 或该评审人可评价。
- 约束：评审人须为项目成员；仍禁止评价自己负责的任务（评审人 ≠ 负责人）。
- 评审人不因被指定而获得任何管理或执行写权限。

### 导师观察者（mentor）

- 概念：复用 `viewer` 角色，**不新增顶层角色**，`ROLE_LEVEL` 不变。
- 加入：通过邀请链接以 `role="viewer"` 加入（由导师本人确认），不走「直接添加成员」。
- 能力：等同 viewer 的只读能力；可被指定为任务评审人（叠加上面的评审权）。
- 可选：在 `memberships` 加 `is_mentor` 标记以便前端区分导师与普通 viewer（待 A/C/D 确认）。
- 不计入负载分析与推荐候选（viewer 本就不进）。

### 落地时的回归测试补充

- 无评审人任务：非 owner 评价返回 403。
- 有评审人任务：被指定评审人可评价；未被指定的其他成员返回 403。
- 评审人是该任务负责人时，评价返回 403（禁止自评）。
- 非 owner、非创建者修改 `reviewer_id` 返回 403。

## 数据隔离规则

- 所有带 `project_id` 的接口必须调用统一项目访问校验。
- 通过任务、贡献、邀请 ID 访问数据时，必须先反查其 `project_id`，再做成员校验。
- 不允许客户端传入 `owner_id`、`actor_id` 等字段绕过当前登录用户身份。
- `viewer` 不得触发任何持久化写入，包括 Agent 消息和会话删除。
- 内部 Agent 工具可以调用只读内部函数，但不得通过公开 HTTP 参数启用“内部模式”。

## 安全响应

- 未登录或会话失效：`401 UNAUTHORIZED`。
- 已登录但不是项目成员，或角色不足：`403 FORBIDDEN`。
- 资源状态不允许当前操作：`409 CONFLICT`。
- 所有错误使用统一结构：

```json
{
  "error": {
    "code": "FORBIDDEN",
    "message": "角色权限不足"
  }
}
```

## 回归测试要求

每次新增写接口必须至少覆盖：

1. 匿名用户返回 401；
2. 非项目成员返回 403；
3. viewer 写入返回 403；
4. member 不能执行 owner 操作；
5. owner 正常完成操作；
6. 跨项目 ID 不能访问或修改数据；
7. 写操作产生 `audit_logs` 记录。
