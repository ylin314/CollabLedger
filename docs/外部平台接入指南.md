# 外部平台接入与体验指南

> 面向：需要在本机或服务器上完整体验 GitHub / 飞书 / 腾讯文档接入的队友。
> 所有密钥只写入本机 `.env`（已被 .gitignore 忽略），严禁提交到 Git 或发到群里。

## 1. 总览

| 平台 | 接入方式 | 能力 | 必需环境变量 |
|---|---|---|---|
| GitHub | OAuth + 仓库绑定 | 提交/PR/Issue/Review 同步、贡献确认、Webhook 实时回传、反向创建 Issue/PR | `GITHUB_CLIENT_ID`、`GITHUB_CLIENT_SECRET`、`GITHUB_TOKEN_SECRET` |
| 飞书 | OAuth（wiki/docx 只读） | 文档资源绑定、更新事件落库、pending 贡献 | `FEISHU_APP_ID`、`FEISHU_APP_SECRET`、`FEISHU_REDIRECT_URI` |
| 腾讯文档 | 访问凭据直连（无 OAuth） | 文档资源绑定、版本/更新事件同步 | `TENCENT_DOC_APP_ID`、`TENCENT_DOC_API_BASE` |

前端入口：项目内「贡献账本」页（owner 可见的集成面板）。平台未配置时点击连接按钮会明确提示缺少哪个环境变量，不会假装成功。

## 2. 通用准备

1. 确认 `.env` 存在于仓库根目录（从 `.env.example` 复制）。
2. 每次修改 `.env` 后重启容器使配置生效：
```powershell
docker compose up -d
```

改了代码才需要 `--build`。验证服务与平台可用状态：

```powershell
curl http://127.0.0.1:8000/api/health
# 登录后查看平台可用性（enabled=false 表示环境变量未配齐）
curl -b <cookie> http://127.0.0.1:8000/api/integrations/platforms
```

3. 打开浏览器访问 `http://127.0.0.1:8000`（后端托管前端），用组长账号登录进入项目。

## 3. GitHub 接入

### 3.1 创建 GitHub OAuth App

1. 打开 https://github.com/settings/developers → 「New OAuth App」。
2. 填写：Application name 任意（如 CollabLedger）；Homepage URL 如 `http://127.0.0.1:8000`；Authorization callback URL 填 `http://127.0.0.1:8000/api/integrations/github/callback`（部署到其他地址时按实际域名替换；契约别名 `/api/github/oauth/callback` 也可用）。
3. 创建后记录 Client ID，点「Generate a new client secret」记录 Client Secret。

### 3.2 生成 token 加密密钥

GitHub 访问令牌使用 Fernet 加密落库，必须提供密钥（`APP_ENV=production` 时缺失会直接拒绝 OAuth）：

```powershell
docker compose exec collab-ledger python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"
```

### 3.3 写入 `.env`

```text
GITHUB_CLIENT_ID=<你的 Client ID>
GITHUB_CLIENT_SECRET=<你的 Client Secret>
GITHUB_TOKEN_SECRET=<3.2 生成的密钥>
APP_ENV=development
COLLAB_FRONTEND_BASE=http://127.0.0.1:8000
# Webhook 演示才需要（见第 6 节）：
# GITHUB_WEBHOOK_BASE_URL=https://<公网地址>
# GITHUB_WEBHOOK_SECRET=<任意随机串>
```

`APP_ENV` 本地演练保持 development；公网部署改 production。`COLLAB_FRONTEND_BASE` 是 OAuth 完成后跳回的前端地址。

重启容器后，贡献账本页 GitHub 卡片显示「可连接」，点击「连接GitHub」会跳转 GitHub 授权页。

### 3.4 体验路径（建议按序）

1. **连接账号**：点击「连接GitHub」→ GitHub 授权 → 回跳后 toast「GitHub 已连接」。
2. **绑定仓库**：在面板中填入仓库（支持完整 URL 或 `owner/name`），点击绑定。仅接受 github.com 地址，其他域名会被 422 拒绝。
3. **同步贡献**：点击同步 → 拉取 commit / PR / Issue / Review 记入贡献账本（首次全量，之后增量）。贡献进入「待确认」，由组长在贡献账本确认后计入统计。
4. **Webhook 实时回传**：见第 6 节（需要公网回调地址，本地可走隧道）。
5. **反向创建 Issue/PR**：面板中分别填写标题/内容（PR 还需 head/base 分支）→ 提交。仅允许向当前项目已绑定的仓库写入，其他仓库返回 403。
6. **断开与重连**：断开会吊销令牌并冻结集成，历史事件与贡献保留；重新连接同名账号自动去重复用。

## 4. 飞书接入

### 4.1 创建飞书应用

1. 打开 https://open.feishu.cn/app → 「创建企业自建应用」。
2. 在「安全设置」添加重定向 URL：与 `FEISHU_REDIRECT_URI` 完全一致（建议填 `http://127.0.0.1:8000/`；OAuth 回调带 `?code=&state=`，前端会自动完成连接）。
3. 在「权限管理」开通：`wiki:read`（知识库读取）、`docx:read`（文档读取）。
4. 发布应用版本并记录 App ID / App Secret。

### 4.2 写入 `.env`

```text
FEISHU_APP_ID=<cli_xxx>
FEISHU_APP_SECRET=<你的 Secret>
FEISHU_REDIRECT_URI=http://127.0.0.1:8000/
```

### 4.3 体验路径

1. 点击「连接飞书」→ 跳转飞书授权 → 回跳后自动连接（前端读取 `?code=&state=` 完成交换）。
2. 在集成面板绑定知识库/文档资源（resource_url 或 resource_id）。
3. 触发文档更新后同步 → 事件落库为 pending 贡献 → 组长确认。

## 5. 腾讯文档接入（官方 Open API 凭据直连）

### 5.1 官方地址与凭据

腾讯文档 Open API 使用固定服务域名，`TENCENT_DOC_API_BASE` **不是从控制台复制的自定义地址**，应填写：

```text
TENCENT_DOC_API_BASE=https://docs.qq.com
```

腾讯文档官方 Open API 每次请求都需要在请求头同时携带：

```text
Access-Token: <用户访问令牌>
Client-Id: <第三方应用 client_id>
Open-Id: <用户 open_id>
```

应用审核后从腾讯文档开放合作平台获得 `client_id`；用户授权或授权码换取流程获得 `access_token` 与 `open_id`。Token 只写入本机连接表单，由后端加密保存，不要提交到 Git。

官方“查询文档”接口示例：

```text
GET https://docs.qq.com/openapi/drive/v2/files/{fileID}/metadata
```

### 5.2 写入 `.env`

```text
TENCENT_DOC_APP_ID=<腾讯文档 client_id>
TENCENT_DOC_API_BASE=https://docs.qq.com
```

### 5.3 体验路径

1. 使用演示账号登录：`owner-demo@example.com / password-123`。
2. 点击「连接腾讯文档」，填写完整 `access_token`、`open_id` 和显示名称。
3. 点击「保存连接」；令牌只会加密存入后端，不会在连接列表回显。
4. 在「绑定飞书 / 腾讯文档资源」中选择「腾讯文档」和「单文档」。
5. 资源 ID 可填写官方 `fileID`；如果填写文档链接中的 `encodedID`（通常以 `D` 开头），系统会先调用官方 fileID 转换接口。
6. `开放 API 路径` 可留空，系统默认使用：

```text
/openapi/drive/v2/files/{fileID}/metadata
```

7. 点击「绑定资源」→「立即同步」。成功后事件先进入 `pending`，由组长确认后才计入贡献主统计。

腾讯文档当前接入范围是官方 Open API 的单文档元信息/更新时间读取；不支持把普通网页链接伪装成 API，也不支持知识空间类型。

## 6. Webhook 实时回传（可选亮点）

Webhook 回调地址必须公网可访问。本地演示推荐隧道：

```powershell
# 方案 A：cloudflared（免费、无需账号）
cloudflared tunnel --url http://127.0.0.1:8000
# 方案 B：ngrok
ngrok http 8000
```

把隧道地址写入 `.env` 后重启：

```text
GITHUB_WEBHOOK_BASE_URL=https://<隧道域名>
GITHUB_WEBHOOK_SECRET=<任意随机串>
```

随机串可用 `python -c "import secrets; print(secrets.token_urlsafe(32))"` 生成。

在集成面板对已绑定仓库点击「注册 Webhook」→ 系统调用 GitHub API 创建 hook（订阅 push / PR / review / issues）→ 在 GitHub 仓库做一次提交，数秒内贡献账本出现 pending 记录。签名使用 HMAC-SHA256 校验，重复 delivery 自动去重。

## 7. 常见问题

| 现象 | 原因与处理 |
|---|---|
| 按钮提示「GitHub 尚未配置，请先在后端设置 GITHUB_CLIENT_ID 和 GITHUB_CLIENT_SECRET」 | `.env` 未配置或未重启容器；补齐后 `docker compose up -d` |
| OAuth 409 `NOT_CONFIGURED: ... GITHUB_TOKEN_SECRET` | 未生成 token 加密密钥（生产环境强制），按 3.2 生成 |
| 提示「redirect_uri 不能为空」（飞书） | 未设置 `FEISHU_REDIRECT_URI`，且前端未传 redirect_uri |
| 提示 `INVALID_STATE` | state 已过期/已使用，或重启后数据库变化；重新点连接 |
| 绑定仓库 422 | 仓库地址不是 github.com 或格式不是 `owner/name` |
| 反向写 Issue/PR 403 | 目标仓库不在当前项目已绑定列表，先绑定该仓库 |
| Webhook 409 `NOT_CONFIGURED` | 缺 `GITHUB_WEBHOOK_BASE_URL` 或 `GITHUB_WEBHOOK_SECRET`，或未先连接 GitHub |
| 同步后贡献没有立即计入统计 | 同步结果先进「待确认」，组长确认后才计入主数字（主统计只计 confirmed） |

## 8. 安全要求

- `.env`、密钥、token 永不提交 Git、永不截图外发；泄露后立即在对应平台吊销并更换。
- 公网部署时设置 `APP_ENV=production` 并提供 `GITHUB_TOKEN_SECRET`；建议同时开启 `COLLAB_COOKIE_SECURE=true` 与 HTTPS。
- 反向写入/Webhook 注册均为 owner-only 操作；普通成员不可触发。
