## 3. 缺陷与复现

1. **授权缺失导致跨项目读取边界不完整（P0/P1）**：`auth_users.py:139-144` 只查共同 memberships，不查 active/status/项目授权。复现：用户退出或被移除项目后仍与目标有历史 membership，继续请求 profile。整改：建立授权表/字段、按项目和用途判定，默认最小权限；撤销后停止画像更新和跨项目推荐。
2. **画像契约字段不足（P1）**：当前 `profile_payload` `profile.py:22-26,234-236` 只返回 D6 深化字段；API 契约 `:2120-2159` 要求项目数、完成任务数、效率、准时率、top_skills、collaboration_types、data_sources。需产品确认采用哪套字段，不能以“字段不同但代码存在”视为完整。
3. **projects_count 数据口径偏宽（P2）**：`profile.py:202-204` 统计所有 memberships，包含 left/deleted 关联。整改统一历史项目口径并在响应说明。
4. **技能出现次数规则可能把 users.skills 的重复词当历史样本（P2）**：`:93-99` member_hits 会计数，需确认技能标签是否应视为能力证据还是仅候选词。
5. **画像前端仅成员弹窗（P1）**：无授权管理、来源明细、合作关系、长期推荐；无法验收完整阶段四。

## 4. 整改顺序

D6-1 先定义授权对象（用户、项目、用途、撤销/删除语义）；D6-2 完成 profile 合约和数据口径；D6-3 实现 collaborations/long-term recommendations；D6-4 接入前端设置/来源/合作页面；D7 做跨项目越权、退出项目、重启和窄屏浏览器验收。

## 5. 验收标准与风险

本人可看自己的完整画像；同项目成员仅在授权范围内可看；离开/撤销授权立即停止跨项目使用；画像数值可由真实 tasks/reviews/work_logs/confirmed contributions 重算；新成员空画像而非假数据；合作关系和长期推荐有真实 API/UI。当前外部无阻塞，但设计授权语义需用户确认后才能编码。
