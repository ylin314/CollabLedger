## 3. 关键修复与根因

1. **周报自动写入**：旧 `GET` 首访直接生成，且工作区 `workspaceQuery` 自动请求该接口。根因是读取与生成复用一个函数。现拆为只读 `get_weekly_report` 与写入 `generate_weekly_report`，前端按钮发 `POST`。
2. **贡献状态混入主数字**：旧查询只 `COUNT(*)`，未过滤状态。现 confirmed 主数和 pending/disputed 分项同时返回，避免“看似完整但不诚实”。
3. **工时双计**：旧代码把任务 `actual_hours` 与打卡 `hours` 直接相加。现逐成员选择来源，保留两列原始值和一列有效值，永不相加。
4. **PDF 假成功**：旧 Helvetica 单行 PDF 不能承载中文正文。现禁用并明确 501，后续若恢复必须接入中文字体并覆盖正文、下载和浏览器验收。
5. **历史 N+1**：旧 history 每条周报单独查询创建人。现一次 LEFT JOIN 返回创建人名称。

## 4. 复现与接口验收

1. 首次 `GET /api/projects/{id}/weekly-report`：断言 `exists=false/stored=false`，并直接查询 SQLite `weekly_reports` 确认行数仍为 0。
2. 周报页点击生成，对同一路径发送 `POST`：断言 `exists=true/stored=true`，检查 `weekly_reports` 仅 1 行。
3. 同周期再次 `POST`：断言 history 仍 1 行、周期唯一、payload 更新。
4. 创建 confirmed、pending、disputed 三条贡献后生成：断言主数为 1，待确认数为 2，`pending_label` 为“待确认 2 项”，pending/disputed 不进入主数。
5. 同一成员完成任务写 `actual_hours=7`，再创建 `task_checkins.hours=2.5`：断言 `task_hours=7`、`checkin_hours=2.5`、`actual_hours=2.5`、`hours_source=checkin`，不是 9.5。
6. 无打卡成员只写任务工时：断言 `hours_source=task` 且有效工时等于任务工时。
7. `GET format=markdown`：只读返回完整 Markdown；`format=pdf` 返回 501，不生成占位文件。
8. 既有 weekly_reports 重启后 GET/history 读取不丢失；SQLite 已有聚焦测试，容器/PG 留 D7。
