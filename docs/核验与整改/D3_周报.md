## 3. 缺陷、复现与根因

1. **未确认贡献计入周报（P1）**：`analytics.py:165` 统计所有未删除 contributions，未加 `status='confirmed'`；与报告逻辑 `:147` 只统计 confirmed 不一致。复现：插入 pending/disputed 贡献后生成周报，`summary.contribution_count` 增加。整改：冻结周报口径，按 D3/贡献文档决定是否只计 confirmed，并补 pending/disputed 验证。
2. **工时双计（P1）**：`analytics.py:166,171-173,182` 将任务 actual_hours 与 task_checkins.hours 相加；同一工作若两处均记录，会重复。复现：同周任务写 actual_hours=3，同时打卡 hours=3，结果可能为 6。整改：明确任务完成工时与打卡工时的唯一计量规则，或标注来源分项后再聚合。
3. **PDF 装饰性占位（P1）**：`_simple_pdf_bytes` 仅单行标题且中文损坏。整改：在产品确认后接入支持中文字体的 PDF 生成；若本阶段不做，移除/禁用 pdf 选项并返回明确错误，不能保留假成功。
4. **历史查询 N+1（P2）**：`analytics.py:303-314` 每条记录单独打开连接查询创建人。整改：JOIN 一次查询。
5. **工作区自动生成周报（P2）**：`frontend/src/app/queries.ts:62-66` 进入工作区即请求周报；需改为明确用户动作或可解释缓存策略。

## 4. 权限/失败/前端核验

周报和风险路由均先调用 `ensure_project_access`（`routers/analytics.py:60-94`）。前端 ReportView 有 refresh/source 展示，但本轮没有浏览器端截图或桌面/390px 实测。非 401 的 workspace 可选请求错误被 `optionalJson` 吞掉（`queries.ts:23-29`），存在静默“空报告”风险。

## 5. 整改顺序

D3 先冻结统计口径并修复贡献/工时；再处理 PDF 契约；之后优化历史查询和前端主动生成；最后由 D7 验证 SQLite 重启、PG、真实 LLM、浏览器。
