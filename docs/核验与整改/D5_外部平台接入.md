# D5 外部平台接入：真实性核验与整改结果

> 初审日期：2026-08-29；整改复核日期：2026-08-30。状态判定坚持“代码存在 ≠ 测试通过 ≠ 真实运行 ≠ 产品完整”。本阶段代码与本地持久化链路已整改；因 `.env` 无任何外部平台凭据，GitHub/飞书/腾讯文档实网主路径仍为**外部阻塞**，不得写成真实完成。

## 1. 权威范围与冲突处理

旧版 D5 方案曾限定“仅 GitHub、单向手动同步，Webhook/反向写入/飞书/腾讯文档不做”。用户已明确撤销该限制，并确认：

1. Webhook 和 GitHub 反向创建 Issue/PR 作为用户可选亮点；
2. 飞书、腾讯文档重新纳入完整 PRD；
3. 外部凭据不足时标记“需要外部资源”，但实现不得使用静态 JSON、假按钮或静默成功。

因此以 `docs/API接口契约.md` 的通用平台字段为对外标准，以团队分工、路线图和项目书的多平台要求为范围，旧“不做”只保留为历史冲突记录。

## 4. 复现方式

### 4.1 本地通用链路

1. 登录并建立平台连接；
2. owner 调 `POST /api/projects/{id}/integrations`；
3. 调 `POST /api/projects/{id}/integrations/{integration_id}/sync`；
4. 查询 events 与 `contributions?source=<platform>`；
5. 再次同步，确认 external event 唯一键使 contribution 不重复；
6. 断开连接，确认 connection revoked、token 为空，但 integration/event/contribution 仍存在。

### 4.2 Webhook

使用相同 JSON body 和 `X-GitHub-Delivery` 发送两次，第一次产生 pending contribution，第二次返回 `duplicate=true`；篡改签名应返回 401。

### 4.3 实网验收（待资源）

```text
GitHub OAuth → 回调 → 绑定仓库 → 四类事件同步 → pending → owner confirm
→ 重复同步 → Webhook 注册/接收 → 显式创建 Issue/PR → 断开 → 重连

飞书 OAuth → 绑定 Wiki/Docx → 同步 document_updated → pending → 重复同步

腾讯文档凭据 → 绑定 API path/resource → 同步 → pending → 重复同步
```

## 5. 根因与整改方案回顾

| 原根因 | 已执行整改 |
|---|---|
| 旧方案把多平台和亮点能力排除 | 更新深化方案与 API 契约，纳入统一平台、Webhook、反向写入 |
| state 只在内存且不绑定主体 | 新增 `oauth_states`，绑定 user/session/TTL/一次消费 |
| XOR 混淆与仓库默认密钥 | Fernet + 生产缺密钥拒绝 + `.env.example` 空值 |
| sync 同时做绑定且 member 可写 | 独立 owner 绑定接口与 owner sync |
| 任一仓库错误全回滚 | 每仓库独立事务，返回 partial |
| 断开物理删除破坏去重 | 软失效，保留历史 |
| 前端隐藏未配置状态与硬编码 owner | 显式“需要外部配置”、owner 门控、真实当前用户 ID |
