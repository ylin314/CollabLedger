# 演示手册（15 分钟全流程走查）

> 面向评审 / 答辩的端到端走查手册，按 D7 §3.3 编写。每个步骤给出「操作 → 预期结果」，截图位用 `截图：<文件名>.png` 占位，演示前用真实截图替换。演示全程使用种子数据，不伪造记录。

## 0. 准备（演示前完成）

```powershell
# 1) 生成/重置阶段二演示数据（会重建 stage2-demo.db）
python scripts/seed_stage2_demo.py

# 2) 指定演示数据库并启动后端
$env:COLLAB_DB="$PWD\stage2-demo.db"
python -m uvicorn backend.main:app --reload --port 8000
```

- 前端：另开终端 `cd frontend; npm install; npm run dev`（访问 <http://127.0.0.1:5173>）；或直接用生产托管 <http://127.0.0.1:8000>。
- `.env`：LLM 可选。有 `LLM_API_KEY` 时推荐/周报/Agent 走 LLM 语义路径；无 Key 时自动回退规则路径并显示降级提示，不阻塞演示。
- GitHub 演示（第 11-13 分钟）需在 `.env` 填写 `GITHUB_CLIENT_ID` / `GITHUB_CLIENT_SECRET`，否则前端显示「未配置 GitHub 接入」。

## 1. 登录与项目空间（0-2 分钟）

1. 用「组长 rxc」登录 `owner-demo@example.com`（密码 `password-123`）。
2. 首次进入会自动落在「阶段二演示项目」空间。
3. 预期：看板显示项目名称、成员列表与任务卡片；右上角显示当前用户「组长 rxc」。

截图：demo-01-login.png、demo-02-project-overview.png

## 2. 打卡、评价与贡献账本（2-5 分钟）

1. 打开工作日志（worklog），对「已完成后端模块」打卡并填写实际工时。
2. 打开任务详情，对已完成任务打分评价（质量 1-5）。
3. 打开贡献账本（contributions）：
   - 新增一条手动贡献（如「编写答辩 PPT 初稿」，来源为手动）。
   - 对他人贡献执行「确认」；再建一条，尝试「争议」。
4. 预期：打卡/评价/贡献都会写库并在对应页面回显；贡献状态在 pending/confirmed/contested 之间流转可见。

截图：demo-03-checkin.png、demo-04-contributions.png

## 3. 推荐与负载/风险（5-8 分钟）

1. 打开任务推荐（recommendations）：选中「未分配后端接口」（或输入任务名），产生候选人列表。
2. 预期：每个候选人卡片给出四项证据标签——技能族匹配 / 质量 / 效率 / 负载；被排出的成员会显示「超负载排除」；无样本成员显示中性分并给出降级提示（degrade-note）。
3. 点击「采纳」某个候选，随后到推荐历史（history）查看批量/单任务、来源、采纳人与改派对象。
4. 打开成员负载页（load）与风险页（risks）：负载按权重计算并排序；风险按严重度降序排列，`critical_unassigned`（关键任务无人承接）显示在最前；LLM 可用时含风险总结。

截图：demo-05-recommendations.png、demo-06-load.png、demo-07-risks.png

## 4. 周报与 Agent（8-11 分钟）

1. 打开周报（weekly-report）：查看本周成员摘要与整体洞察；切换 `markdown` 视图导出。
2. 打开周报历史（history）：确认生成记录已落库，可按周回看，支持 refresh 覆盖。
3. 打开 Agent 对话（agent）：提问如「给后端接口未分配的任务推荐最合适的人，并说明理由」。
4. 预期：Agent 多步推理（先规划工具再读取任务/负载/风险/推荐器）；回复带工具轨迹（tool_trace）与来源引用（citations），每条结论可点击回看证据。

截图：demo-08-weekly-report.png、demo-09-agent.png

## 5. GitHub 接入同步（11-13 分钟）

1. 用「后端同学」登录；打开 GitHub 连接页，点击「连接 GitHub」，跳转 OAuth 授权。
2. 授权回调后回到页面；预期显示已连接账号（`connected=<login>`）。
3. 在项目内配置仓库 `owner/name`，点击「同步」。
4. 预期：同步产生 `source=github` 的 pending 贡献（提交与 PR），每条带来源徽标与 evidence 链接；重复同步自动去重（skipped 计数）。之后在贡献账本中确认这些记录。
5. 结束时用「断开连接」演示 token 清理（可选）。

截图：demo-10-github-connect.png、demo-11-github-sync.png

## 6. 成员画像与总结（13-15 分钟）

1. 打开成员列表，进入「组长 rxc」画像页。
2. 预期：画像聚合跨项目数据，展示技能 / 质量 / 效率 / 贡献四个维度，含时间衰减；本人在自己画像页可见，同项目成员互相可见。
3. 切换到非本项目成员视角验证：无权限成员访问画像返回 403（越权防护）。
4. 打开报告页（report / contribution-report）：核对整体统计与成员明细（任务数、质量、实际工时、贡献列表）。
5. 收尾：退出登录（右上角登出）。

截图：demo-12-profile.png、demo-13-report.png
